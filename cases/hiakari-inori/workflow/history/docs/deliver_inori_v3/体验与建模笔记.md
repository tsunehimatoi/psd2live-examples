# 绯灯 祈 建模与体验笔记

## 角色
狐耳巫女 x 机能风:左右不对称发型(左编发、右低双尾)、异色瞳、狐狸半面具、分离式宽袖、腰封铃铛、纱裙、过膝袜与吊袜带、三条狐尾。拆成 37 层(头部 21 层、身体与尾巴 16 层)。

## 流程
1. 用 codex 生成全身母版,再生成严格正面的头部特写(第一次就是正的,吸取上个角色头歪的教训)。
2. 用 codex 并行(最多 8 路)按部件生成绿底图层,要求补画被遮挡部分。31 张里 1 张(前发)首次失败,重试成功。
3. 抠图后对齐。**这是最耗时的一步**:codex 画每个部件时会按自己的尺度重绘,偏移 10 到 90 像素、缩放 0.6 到 1.4 倍都有,而且手臂(右)姿势还不一样。
   - 有纹理的大部件(靴、袜、裙、腰封、上衣、袖、尾巴、颈带、前发)用特征点匹配加相似变换,特征点内点比例高,结果可靠。
   - 眼睛部件用"带缩放的多起点匹配"才找回正确尺寸(睫毛约 0.8 倍,虹膜约 0.7 倍)。
   - 眼白、眉毛这类低纹理部件对不准,借用同侧睫毛的变换。
   - 脸底层被画得过长,按下巴和脸颊位置做纵横不同比例的缩放。
   - 右臂换成左臂镜像,因为生成的右臂是另一个姿势。
   - 对齐用叠图肉眼复核,数字指标(误差、置信度)多次给出矛盾结果,不能只信数字。
4. 身体层用 Real-ESRGAN 放大 2 倍后再变换,头部层直接缩小。
5. 拼 PSD(按 PSD2Live 命名规范:ears-l/r、eyewhite-l/r、handwear 1/2、tail 1..3、headwear 1/2、back hair 2/3 等),导入后 37 层全部被识别成对应部件。
6. 给三条尾巴手动加了摇摆参数和物理(PSD2Live 自动物理只有前后发、果冻眼)。

## v2:腿再分一次
1. 可见部分直接用母版像素:母版腿部区域用 Real-ESRGAN 放大 2 倍(和画布坐标一致)。按裙子 / 腰封 / 袖子图层的 alpha、背景色、吊袜带颜色,算出每条腿、每只靴的可见遮罩。
2. 左右腿的分割线:逐行找两腿之间的背景缝,两腿贴在一起的膝盖段用插值。
3. 被遮挡部分交给 codex 内置的 image_gen 补画,6 个任务并行:两侧大腿上部(裙下、吊袜带下、纱裙下)、画面右腿压在下面的内侧条带、两侧靴内的小腿和脚、下层靴的内侧。输入是精确裁切 + 洋红色遮罩,回贴时只取遮罩内的像素。
4. 检查结果:可见区域与母版逐像素一致。内部 p99 差值 = 0,完全一致的像素比例:袜腿 99.4%、靴 99.3%、吊袜带 99.8%。边缘 2 像素有羽化,平均差约 10/255。
5. 重新导入 PSD 后,手动重建尾巴 swing(目标写 ArtMeshTail / ArtMeshTail2 / ArtMeshTail3,不带 mesh: 前缀)和 PhysicsTails。

## v3:大腿补全,grok 与 codex 对比
- 遮罩扩大到大腿根部(约 y=1250,远在裙子和腰封下面)。腿外侧顺着可见轮廓往上外推,内侧一直画到两腿中间。生成图里在腿外的绿色部分抠成透明,所以顶部是自然的胯部弧线,不是一条直线。画面左腿(角色右腿)的顶部按右腿弧线镜像修形。
- 膝盖内侧浅色线:先把两腿接缝两侧 ±22px 内偏亮的可见像素(约 3000 个)标成遮挡区,再从生成图取像素填回。所以袜腿区域与母版完全一致的像素比例从 99.4% 降到 98.4%,这是有意的。
- **grok -p 与 codex exec 对比**(同一裁切、同一遮罩、同一提示词,并行跑):
  - 内容审核:大腿补画 codex 被拒 1/2(sexual 类),grok 被拒 2/7。膝盖接缝 codex 被拒,grok 通过。两边都没有改写提示词绕过审核。
  - 速度:codex 约 1.5 分钟一张;grok 一个任务 10 到 25 分钟,它会反复"自我修正",有时还会退回到用代码平滑或取色填充(knee_g1 的成品就是这种,已作废)。所以最后直接从 `~/.grok/sessions/<cwd>/<id>/images/` 里取 grok 每一轮的原始生成图。
  - 构图对齐:grok 生成图和输入宽高比相同,缩放后可见区域平均误差 3.7 到 8 / 255,不用再做对齐。codex 输出由它自己贴回原图,误差为 0。
  - 质量:大腿两侧选 grok(胯部弧线和光影自然)。codex 那张(thigh_R_c1)顶部是一条直线截断,未采用。脚、靴、膝盖下层条带保留 codex v2 的结果,grok 那几张脚被画平、靴子细节变少。膝盖接缝用 grok(knee_g1 第 2 张生成图)。
  - 中途 PSD2Live GUI 进程不见了,MCP 连接被拒。用 install_log 里的命令重启后,令牌还在,无需重设。

## 体验问题(PSD2Live)
- 自动物理不包含尾巴、狐耳、面具流苏,需要手动 swing + physics,而且 swing 目标要写成不带前缀的 mesh 名(`ArtMeshTail`),带 `mesh:` 前缀会报"目标不存在",和 `workspace_inspect` 返回的写法不一致。
- `workspace_inspect objects` 分页时没有说明如何翻页(`cursor` 不是合法字段,实际要用 `offset` 或 `query`)。
- 多个同角色图层(如多个 tail)命名顺序和网格名顺序不一致(tail 1 对应 ArtMeshTail2),容易接错。
- 导出 webm 比其他目标慢很多(约 1 分钟,其他目标约 1 秒)。
- 没有"替换图层、保留绑定"的重新导入:import_psd 只能新建工程,手动加的 swing 和自定义物理全部丢失,只能重建。
- 自动生成的腿部对称组(DeformPair_*)没有任何参数轴,腿部动作要自己做关键帧。
- 同一 role 的多层网格编号和 PSD 顺序不直观(legwear 3 对应 ArtMeshLegwearL/R,legwear 1 反而是 L3/R3)。
