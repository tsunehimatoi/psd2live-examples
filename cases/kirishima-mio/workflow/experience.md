# PSD2Live v3.4.2 (Linux x64) 使用体验笔记(全身版)

测试身份:有一点 Live2D 基础、想要一个好看的直播模型的建模师。目标是做出可用的高精度原创角色「雾岛 澪」,测试是次要的。
只记录现象、体验和使用上的坑,没有去查代码 bug。第二轮(全身版)的内容在第 5 节,第 0~4 节是第一轮(半身版)的记录,其中大部分结论两轮都成立。

## 0. 结果概览(全身版)
- 角色:银灰半长发+蓝挑染、浅蓝眼、藏青水手服+蓝蝴蝶结+白袜+棕色乐福鞋,正面全身站姿。
- 画布 2048×3072,PSD 共 27 层(后发、腿皮肤×2、袜子×2、鞋×2、裙子、上衣、双臂、脖子、领子、蝴蝶结、脸、鼻、眼白/虹膜/睫毛/眉×各2、闭嘴/张嘴、前发),PSD2Live 全部自动识别,无 Unknown,左右侧别正确。
- 能做:转头(X/Y/Z)、身体摆动、呼吸、眨眼、张嘴、眼球、眉毛、头发和裙摆物理,导出 moc3、cmo3、VTube Studio 包、4 个动作。
- 交付物见 `README.md`。

## 1. 好的地方
1. 命名规范的 PSD 几乎零配置:`back hair / front hair / face / neck / topwear / neckwear / handwear-l|r / eyewhite-l|r / irides-l|r / eyelash-l|r / eyebrow-l|r / mouth close / mouth open / nose` 全部一次识别,左右也按 `-l/-r` 后缀判对了。
2. 给了"mouth close + mouth open"两张嘴之后,张嘴参数能真正露出口腔、牙齿和舌头(只给一张闭嘴图时,张嘴只是把线条拉开,不像嘴)。对直播对口型很关键。
3. 从导入到出 moc3/cmo3 在 CLI 下只要约 8–10 秒(2x 高清的 19 层也是),并且同时导出 can3、physics3、4 个动作文件。
4. MCP 非常好用:`view` 的 `render_poses` 可以一次渲出 9 个姿势的对比图,不动用户当前的滑条;`workspace_overview/inspect` 能读到图层识别结果和全部 rigTuning 参数。QA 全靠它。
5. CLI 不需要 DISPLAY,可以直接对 PSD 做 `export --target png-sequence/gif/webm`,不需要先建工程。
6. 导出目标很全(moc3 / cmo3 / VTube Studio / p2lrt / web / 视频 / 序列帧等)。

## 2. 问题与体验不佳(按严重程度)
1. **异常退出后的恢复**:本次中途环境重启,GUI 进程被强行结束。重新启动后,GUI 弹出了"恢复未保存的编辑——PSD2Live 在 mio.psd2live 保存或放弃更改之前就关闭了,编辑内容仍在磁盘上,要恢复吗?"(恢复/放弃)。这个设计很好(崩溃恢复是有的)。小问题:这个模态对话框会盖住主窗口,脚本/MCP 之外的操作必须先处理它;对话框没有说明恢复的是哪个时间点的编辑。
1b. **恢复对话框曾经卡死**:重启后第一次打开出现的"恢复未保存的编辑"对话框,点"恢复"、按空格/回车都没有反应,进程 CPU 0%,主窗口始终没出现;此时 MCP 端口仍然可连。我只能强杀进程、清掉 `~/.psd2live/agent-workspaces`(已备份到 art/recovery_bak)才重新启动。另外普通 kill 杀不干净,再次启动会提示"PSD2Live 已在运行",需要 `kill -9`。
2. **噪点透明度会被当成实体**:抠图时背景残留了 3%~10% 的极低透明度噪点,PSD2Live 不报错也不提示,直接把噪点所在的整个包围盒当成网格,渲染出一整块洋红/黑色方块。建议导入时给"图层包围盒远大于有效内容"的警告,或提供"alpha 阈值预览"。(设置里有 alphaThreshold=8,但我是从渲染结果才反推出问题的。)
3. **GUI 在无 GL 环境走软件渲染**:有 `Cannot create Linux GL context` 的 Skiko 报错,自动降级;可用但点击后画面刷新有 1~2 秒延迟,有几次要点两次才生效(Mesh 标签、File 菜单)。
4. **头部转动在 GUI 预览里 Angle X=45 看起来幅度偏小**(MCP 离屏渲染 ±45 的效果比较自然,所以可能只是 GUI 预览上的差异);另外 rigTuning 里的参数很多(上百个),没有"一键更夸张/更保守"的预设,新手很难知道该动哪一个。
5. **设置散落在多处**:Settings 菜单只有界面缩放/主题/语言(Environment 页显示分辨率 1920×1200、建议缩放 115%,但桌面实际是 1280×800,数字对不上);头部/身体强度在右上 Model presets 的 "Rigging & Facial"(数值框看起来是空的);网格密度在右下 Mesh 标签;物理在 Model presets 的 "Physics & Simulation" 和独立的 Physics/Simulation 标签。找一项设置要跑三四个地方。
6. **图层表信息密度低**:Type 列全是 "Preset",真正有用的识别结果在 Binding 列;ID 列被截成 `Ri…`/`Left`/`Both`。
7. **窗口默认尺寸偏小**(约 850×540),要手动最大化才能用。
8. **MCP 令牌拿不到**:只能在 GUI 的 Tools → MCP… 对话框里看,无头用不了;我只能在对话框里把令牌改成自己设的值(要 32–256 位)。后来盒子重启后令牌还在,说明有持久化。
9. **MCP 与 GUI 共用同一个工作区**:脚本调用 `import_psd(discard_unsaved=true)` 会直接替换 GUI 里正在编辑的工程,标题栏出现 `*`。
10. **MCP 参数命名不一致**:`workspace_get_operation` 要 `id`,`workspace_call` 要 `operation`;`wait_ms` 超过 30000 会报错。小事,但容易踩。
11. **默认视频/GIF 导出体积很大**:idle 动作 12 秒、30fps、900px,GIF 达到 75 MB,序列帧 360 张。没有"估算体积"的提示。
12. **张嘴素材在闭嘴状态会多出一条细线**:打开 `mouthOutlineEnabled`(默认)时,闭嘴时会出现双线;关掉后干净。可作为推荐设置写进文档。
13. 同名图层(多个 eyewhite/irides…)会弹警告,实际靠稳定 ID 区分,不影响结果。
14. 安装:release 包不含文档和示例 PSD,需要另外 clone 仓库;GUI 没有 `--lang`。详见 `install_log.md`。
15. 保存的 `.psd2live` 工程文件权限是 `0600`,和其他导出文件不一致(分享时可能踩坑)。

## 4. 美术拆层流程的经验(不是 PSD2Live 的问题,但决定了成品质量)
- 内置 GenerateImage:宽高比参数无效,参考图只是风格提示,做不到"位置不变的局部编辑",所以不适合拆层。
- HuggingFace 免登录 ZeroGPU 的分层/编辑 space 基本都被配额挡住。
- ChatGPT(gpt-image)的编辑最好用:"只保留某部件+补全被遮挡处+绿底"能按要求输出,约 40–120 秒一张;但**每一张的缩放/位置都会漂**,同一对话里也会变画布比例,必须自己做地标对齐(双眼用两个 blob 的中心/宽度,头发和脸用手工地标)。
- 色键抠绿底时,细发丝和半透明阴影(比如腮红)会被抠坏;腮红这一层因此舍弃(后续如要做腮红,应该让模型在白底上出图再用"正片叠底")。
- 4x 放大要先按图层包围盒裁出再放大,再按对齐变换一次性缩到 2x,这样能保留线条质量。
- Read 图片会按路径缓存,同一个文件名预览多次会看到旧图;预览要换文件名(这点是我自己的工具坑,不是 PSD2Live)。

## 5. 第二轮(全身版)的体验与经验
用户反馈第一版"有接缝、五官细节不够、不是全身",所以整条流程重做。

**做法**:ChatGPT 生成全身母版 → 另生成一张只含头部的高精度特写(五官更细)→ 头部 10 层、身体 8 层各自在 ChatGPT 里"只保留该部件+补全被挡住的部分+纯绿底"生成 → 色键抠图 → 头部用 ECC 配准、身体用手工地标+ECC 配准 → 头部整体按相似变换(缩放 0.287、旋转约 3°)放回全身画布 → 2x 合成 → 按规范命名写 PSD → PSD2Live。

**效果**:接缝处(领子/脖子/上衣、袖口/手、袜口/腿、裙摆/腿)在转头、身体摆动、呼吸的姿势下没有肉眼可见的缝隙;五官比第一版精细很多;全身可用。

**第二轮踩到的坑**(多数是美术工具链,不是 PSD2Live):
1. ChatGPT 的内容过滤:"单独输出腿部皮肤"这一层被拒绝(两次,理由分别是"欺诈"和"裸露/性内容"),角色是高中生设定,可能被保守判断。我没有改写提示词绕过,改成:袜子照常补全生成,大腿/膝盖皮肤从全身母版直接取(这块本来完全可见,只有裙下约 35 px 和袜口下约 10 px 的被遮部分用相邻像素向外延伸补出)。所以腿皮肤这一层**不符合"全部由图像生成补全"的原则**,这是本次成品里唯一的例外。
2. 每个部件生成后的缩放和位置各不相同(身体层缩放在 0.35~0.88 之间),必须逐层配准;袖子、上衣这种大面积同色层 ECC 不稳,最后靠手工量地标+重叠对比(半透明叠加原图)才对准。
3. 生成的"上衣"没有袖子也没有领子,正好利于拆层;但"左臂"层的比例与"右臂"层不一致,不能直接镜像复用。
4. 鼻子高光 ChatGPT 生成的是一个带描边的菱形,放进去显得突兀,最后把不透明度降到 40%。
5. 头部特写母版和全身母版的脸并不一致(特写更好看),最终用特写的脸+全身的身体,发型有细微差别但在成品里不突兀。
6. 工作区中途被重置过一次,丢了一批文件;重要中间文件应及时备份。

**PSD2Live 方面的新发现**:
- 2048×3072、27 层的 PSD 在 MCP 下导入约 2 秒,导出 moc3+cmo3 约 2 秒,很快。
- 纹理被打包成一张 4096 图集(约 4.3 MB),VTube Studio 导出报告提示"面部追踪只驱动标准参数:20 个里的 15 个"。
- GIF 导出(idle 12 秒、1024 px)文件有 40 MB 以上,和第一轮一样没有体积提示。
- MCP 的 `view` 工具渲染全身 3072 px 只要不到 1 秒,很适合反复看细节。
- 参数和 `render_model` 的 `viewport` 必须显式给出 `{mode:canvas_rect,...}`,第一次调用容易漏。

**第三轮:用户反馈"脸歪了"后的修正**
- 原因:ChatGPT 生成的头部特写本身就有歪头——两眼连线倾斜约 1.7°,耳朵一高一低;我又把特写按 SIFT 求得的相似变换(含 3° 旋转)放进全身画布,结果两眼连线变成约 -4.7°,眼睛还比脸的中线偏左约 12 px,于是看起来整张脸歪。
- 处理:眼睛、睫毛、眉毛整体旋转摆平并移到脸的中线上;再以视觉右侧的眼睛、眉毛、睫毛为准镜像出另一侧(虹膜保留各自原图,只移到对称位置,避免高光方向反过来);脸底层以视觉右半边镜像到左半边,耳朵、腮红、下巴都对称;嘴和鼻子居中。
- 这是对称化处理,不是拆层的硬切;代价是左右脸细节完全一样,少了一点手绘的自然差异。更彻底的办法是让 ChatGPT 重新生成严格正面、对称的头部特写并重做 10 个头部层,耗时更长,这次没有做。
- 体验上的启发:AI 生成的"正面"头像常有轻微歪头,拆层前最好先量一下眼线和耳线的角度,而不是只和母版对位。

## 附:第四版(正脸重做)补充记录
- 用户反馈"脸歪了"后,重新生成严格正面、对称的头部特写母版(ChatGPT 生成了两次才得到可用的),并重做全部头部 11 层。ChatGPT 每次重绘都会改变脸宽、下巴位置和刘海形状,所以不能直接叠回去,只能按眼、嘴、耳的位置逐层缩放放置;脸底层按耳宽和下巴位置做了横纵不同比例的缩放。
- ChatGPT 分层图的绿底抠图后,嘴唇和发丝边缘会带绿色或彩色的边,需要额外做去绿边处理(这是我的流程问题,不是 PSD2Live 的问题)。
- 新生成的前发刘海比母版更遮眼,所以把眼白、虹膜、睫毛放在前发图层之上(常见的"眼睛透过刘海"做法);PSD2Live 导入后没有出问题。
- 脖子层 ChatGPT 补成了很宽的肩膀皮肤,会在肩头露出来,我用一个梯形遮罩把脖子限制在领口以内(这属于被衣服盖住区域的裁剪)。

## 附:第五版(脖子补画 + 脸放大)
- 脖子层用 ChatGPT 向上补画:原先上缘是被下巴切出的 V 形缺口,现在补成延伸到脸后面的完整脖子圆柱(上缘平直,带下巴投影)。ChatGPT 前两次重绘会改变肩形,第三次强调"其余像素保持不变"后位置基本一致(边缘偏差 1 像素以内)。
- 脸(脸底层、五官、耳朵)整体放大 16%,头发大小不变。
- 转头、低头、身体摆动时检查过,没有看到脖子或其他层之间露底。其余互相遮挡的层(躯干/裙/腿/袜/手臂/眼睛部件)原本就是完整补画的。
