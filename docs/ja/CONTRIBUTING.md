# 投稿ガイド

[中文](../../CONTRIBUTING.md) · [English](../en/CONTRIBUTING.md) · [한국어](../ko/CONTRIBUTING.md)

PSD2Live に関する素材、プロジェクト、制作フロー、プロンプト、Skill、MCP シナリオを歓迎します。未完成や失敗の試みにも参考になる価値があります。

**最低限の要件**：サンプル 1 つ（素材、プロジェクト、モデル、プロンプトなど）と、意味のある説明を一、二文。何をしたか、どうなったか、どこでつまずいたかなど。以下のその他の内容はすべて任意です。

**言語は不問**：投稿はどの言語でも構いません。翻訳は不要です。

**広告禁止**：宣伝リンク、集客のための連絡先、有料サービスや商品の宣伝を含めないでください。作者のクレジットと必要な素材の出典は広告に当たりません。

## 投稿方法

- **Issue**：Git は不要です。[ケース投稿](https://github.com/tsunehimatoi/psd2live-examples/issues/new/choose) のフォームに記入すると、メンテナーが以下のルールに沿って整理して公開します。
- **プルリクエスト**：以下のルールに沿ってディレクトリを作成し、提出前にローカルチェックを実行します。

## 投稿ルール

### 構成

投稿はそれぞれ `cases/` 以下の 1 ディレクトリで、関連する内容をすべてその中に置きます。サブディレクトリは必要に応じて作成します：

```text
cases/
└── <id>/
    ├── README.md         入口ページ（必須）
    ├── manifest.json     素材マニフェスト（素材パックがある場合。メンテナーが補完可能）
    ├── preview.webp      プレビュー（任意。GIF も可）
    ├── workflow/         手法、スクリプト、ノート
    ├── prompts/          プロンプト
    ├── skills/           Skill。ホストが必要とするネイティブ構成のまま
    └── mcp/              MCP 呼び出しシナリオ
```

- `<id>` には小文字、数字、ハイフン、アンダースコアを使います。例：`kirishima-mio`。
- プロンプトや Skill だけの共有も 1 件の投稿です。`README.md` と対応するサブディレクトリがあれば十分です。
- 複数のケースで共有する内容はいずれか 1 つのケースに置き、他のケースからは相対リンクで参照します。コピーはしないでください。
- [ケース一覧](../../cases/README.md) とトップページのケース表にそれぞれ項目を追加します（メンテナーが行っても構いません）。他の言語版はメンテナーが同期します。

### README

意味のある説明が一、二文あれば十分です。以下の項目は必要に応じて記入します：

| 項目 | 説明 |
| --- | --- |
| 概要 | 何をするか、結果はどうか。[プレビュー](#プレビュー)を添えて |
| 環境 | PSD2Live のバージョン。AI を使う場合はクライアントとモデル |
| 使い方 | 入力、手順、期待される結果 |
| 既知の問題 | 不十分な点、失敗した試み |
| 出典 | 作者、素材の出典。CC0 以外の場合はライセンス |

未検証の内容は冒頭に「未検証」と記載します。例として [tml](../../cases/tml/README.md) を参照してください。

`mcp/` のシナリオには、素材のバージョン、psd2live の commit、前提状態、呼び出し、アサーションも記載します。書き込みを行うシナリオは独立したワークスペースと出力ディレクトリを使います。一度の Agent 実行は回帰テストの代わりにはなりません。

### ファイル

- Git 内の 1 ファイルは 5 MB 以下とし、`.psd`、`.cmo3`、`.moc3`、`.zip` などのバイナリはコミットしません。素材、プロジェクト、書き出しパックは Release で配布するので、プルリクエストにはダウンロードリンクを添えるだけで十分です。
- トークン、セッション ID、アカウント情報、個人的なパスは削除し、プロプライエタリな SDK のバイナリはアップロードしないでください。

### プレビュー

結果がはっきり分かれば十分で、形式やサイズは自由です。静止画、GIF、WebP のいずれでも構いません。PSD2Live の **ファイル → 形式を指定して書き出し → GIF…** で作成できます。書き出したモデルがあれば、本体プロジェクトでビルドした Cubism プレビューライブラリで直接レンダリングすることもできます：

```sh
python scripts/render_preview.py <モデル>.model3.json cases/<id>/preview.webp --renderer <live2d_renderer のあるディレクトリ>
```

Pillow と libwebp 対応の ffmpeg が必要です。プレビューライブラリのビルドは本体プロジェクトの `native/live2d_renderer/README.md` を参照してください。

### 素材マニフェスト

素材パックのある投稿には `manifest.json` が必要で、`catalog.json` に登録し、`scripts/fixtures.lock.json` を更新します。慣れていない場合は README と素材のリンクだけを提出すれば、メンテナーが補完します。

- 必須：`schema_version: 1`、`id`、`version`、`title`、`description`、`author`、`tags`、`source`、`compatibility`。`license` の既定値は `CC0-1.0`。
- `source`：Git の出典は `commit` に完全な SHA を固定します。ローカルからの取り込みは `kind: local-import` とし、`name`、元ファイル一覧の `inventory_sha256`、`imported_on` を記録します。Git の出典を捏造しないでください。
- `archive` には HTTPS URL、`size_bytes`、`sha256` を、`files` には各ファイルの `path`、`size_bytes`、`sha256` を記録し、パスは `<id>/` で始めます。既存のマニフェストを参考にしてください。

## ライセンス

ライセンスの記載がない投稿は [CC0 1.0](../../LICENSE) で公開され、作者と出典は README またはマニフェストに残します。投稿によって、その内容を共有する権利があることを確認したものとみなします。

## ローカルチェック

```sh
python scripts/validate.py
python -m unittest discover -s scripts -p 'test_*.py'
```

CI でも同じチェックを実行します。

## 素材の公開（メンテナー）

```sh
python scripts/pack.py tml --source-repository ../psd2live --release-tag assets-v1
python scripts/validate.py
```

- パッケージャーはケース内の Git で追跡されている素材のみを含め、Markdown は含めません。
- `build/assets/` 以下のパックを対応する Release にアップロードします。素材が変わったらケースのバージョンを上げて新しい添付ファイルの URL を使い、既存の添付ファイルは上書きしません。
- GitHub の添付ファイルサイズ上限を超える素材は外部の HTTPS ストレージを使えます。マニフェストの形式は変わりません。
- 本体プロジェクトは、レビュー後に別のプルリクエストでのみ素材のロックファイルを更新します。
